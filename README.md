# おやこうこうかん日記

## 1. サービス概要

このアプリ「おやこうこうかん日記」は、**要介護者**(介護を要する人)の日常の様子を**主介護者**(同居の家族)が記録として残すことができるアプリです。

記録方法を**選択ボタン**や**文字入力**のみで行うことができる。
体調であれば**良い**、**普通**、**悪い**の3種類

主に以下の2点で役立てることができます
- 家族の状況を一緒に暮らせていない家族が情報共有できる
- 病院受診、介護サービスの利用の際にすぐに記録を見れる

---

## 2. このアイデアはどこから生まれたか

#### 介護の現場で15年以上勤めた視点から
- 離れて暮らす家族は普段の様子がわからない
- 離れて暮らす家族が連絡をして様子を聞いても、連絡をした時の様子しか見えてこない
- 主介護者が高齢化してきていることで、自分でどうにかしないといけないと負担になってしまっている時があった
- 介護サービス利用時や病院受診時に生活状況を確認しても曖昧な状況しか答えることができない

**電話の普及で連絡は取りやすくはなっているが、病気や怪我などがあった時以外あまり連絡をしない、連絡をすることはあっても普段の様子が見えにくい状況が多く見られた。**
**普段から日常の様子を記録し、情報共有をしておくことで協力を得やすくなると考えた。**

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

- 離れて暮らす家族が連絡を取る時間があまりなく、要介護者の様子や主介護者の負担が見えにくい
- 介護サービス利用や病院受診の際に詳しく情報共有ができないことがある

---

### 3-2. 本当に解決したい課題は何か

- 離れて暮らす家族へ情報共有を行うことで、要介護者の普段の様子を知ることができる
- 離れて暮らす家族へ情報共有を行うことで、主介護者の負担が多くなってないのかを確認できる
- 介護サービスや病院受診の際に情報共有をしっかり行うことで、適切なサービスや適切な治療に繋げることができる
- 現状のアプリについて、簡単な操作であれば必要な情報が共有しにくい、情報共有を行おうと思えば記録が多岐に渡り操作がわかりにくい課題がある

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

ターゲット設定：
  - **メインターゲット：同居している主介護者(主に要介護者の配偶者や子供世代)**
    - ITリテラシー：電話やメールの返信はできるが、複雑なアプリ操作は困難
    - 理由：簡単なボタン操作やメールのような文字入力方法にすることで、不安なく取り入れることができる

  - **サブターゲット：離れて暮らす家族(要介護者の子供世代)**
    - ITリテラシー：電話やメール、通常のアプリを使用できる程度であれば問題はない
    - 理由：アプリ一つで離れて暮らす家族の状況を知ることができ、安心を得ることができる
  
---

### 4-2. 自分とユーザーの距離

**(体験談)**
- 義父が認知症になり在宅で義母と二人での生活をしている状況
  - 普段連絡はするにしても何気ない用事や世間話程度
  - 帰省した際に義父と話した時に**話が噛み合わない**などの認知症の進行が見られた

- 実家が近くても仕事が忙しくあまり帰省できず、連絡も少ない
  - 月に1回程度帰省するが、父の身体つきが細くなっている
  - 体調に気遣うも「大丈夫」と心配させないようなが素振りが見られる

---

### 4-3. 実際に使われる可能性について

**(需要)**
- 介護サービスを利用しながら自宅で生活する人は約448万人
- 半分は在宅介護を利用されている
- 老々介護も増加傾向
- 主介護者も要介護者になる可能性
- 主介護者が怪我や病気になる可能性
  - 離れて暮らす家族がすぐに駆けつけることができたとしても、要介護者が普段どのように過ごしていたのかを知ることは困難

**(既存の代替手段と課題)**
- 連絡手段として多くは電話・LINE
  - 定期連絡(週1回程度)
  - 休みの日にまとめて連絡 
  - 家族の体調に変化がなければ連絡はしない
  - 主介護者も家族に負担をかけたくないと連絡を控えることもある
  - 主介護者の負担については更に連絡を控えることも多く見られる
  - 話を聞いた時の状況でしかわからない
- 帰省した時に生活状況を確認
  - 帰省した時の状況しかわからない

**(アプリの価値：既存の手段から乗り換えるのか)**
- 日々記録をつけることで状況(体調・食欲・睡眠など)を知ることができる
- 記録が蓄積することで状況の変化に気づきやすくなる

### 主介護者は記録をつけることで、精神的負担なく家族へ状況を伝えることができる
### 離れて暮らす家族は記録を見ることで、状況の変化、主介護者の負担に気づくことができる

---

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

- 離れて暮らす家族が勧める(メインの導入きっかけ)
  1. 離れて暮らす家族が、要介護者の状況を把握するために導入
  2. 設定を一緒に行い、操作を説明する
  3. アプリを使うことで要介護者の状態把握ができる
  4. 主介護者の負担も気づきやすくなる
  5. 要介護者の状況を一緒に確認できることにより安心感につながる

- 主介護者が見つける(サブの導入きっかけ)
  1. 要介護者の記録をつけたいと考え検索
  2. 記録が簡単なもので負担が少ない
  3. 記録の負担が減ることで継続利用につながる

---

## 4-5. 最初に使ってもらいたい具体例

- 義母(メインターゲット) 義父と二人暮らし
  - 普段仕事をしている
  - 家族優先で過ごすことが多く、自分のことは二の次
- 義父
  - 認知症が見られる
  - 日中は一人で過ごす時間がある
- 妻(サブターゲット)
  - 実家までは車で2時間程度
  - 現在の連絡手段
    - LINE：用事がある時のみ(週1回程度)
    - 電話：緊急の用事がある時のみ(緊急時のみ)

- 導入方法について
  - 「義父の状況をこのアプリで簡単に状況を伝えて」と妻より義母に使い方を説明
  - 設定を一緒に行い導入
  - 記録をしてもらうことで情報共有を行い協力体制を図る

## 7. このアプリで実現すること

### MVPで作る機能

- トップページ：サービス概要、ログイン・新規登録への導線
- ログイン：メールアドレス、パスワード
- 新規登録：アカウント作成(氏名、メールアドレス、電話番号、パスワード、パスワード確認)
- ホーム画面：記録をつけるボタン、記録をみるボタン、マイページボタン、要介護家族情報ボタン
- 記録新規作成ページ：
  - 体調(良い・変わらない・悪い)
  - 食欲(ある・変わらない・ない)
  - 睡眠(多い、変わらない、少ない)
  - 特記事項
  - 各ページ戻るボタン設置
- 記録確認ページ：記録作成日時での確認ができる
  - 記録詳細ページ：体調、食欲、睡眠、特記事項を確認、戻るボタンを設置
    - 記録編集機能
- マイページ：アカウント情報表示
  - 要介護家族登録：要介護者の情報登録(氏名、生年月日、血液型、病気(大きな病気3個程度))
  - 家族登録：アカウント作成(氏名、メールアドレス、電話番号、パスワード、パスワード確認)
  - マイページ機能の拡張：アカウント編集(家族アカウント含む)
  - 要介護家族情報編集

### 本リリースで作る機能

- パスワード再設定：パスワードリセット機能
- 要介護家族登録機能の拡張：介護保険証の写真登録できる機能を追加
- 体調不良時通知機能：
  - 記録保存時に「体調：悪い」「食欲：ない」「睡眠：少ない」が選択
  - 家族へメール通知
- 電話番号でのログイン機能
  - 主介護者が高齢の場合メールアドレスを覚えていないことが考えられるため

## 8. このアプリの懸念点とその対策


### 懸念点

- 問題点：主介護者が配偶者の場合
- 理由：普段PCやスマートフォンにあまり触れない場合に記録をする負担が出てくる
- 対策：選択的なボタン操作で簡単な記録ができることで負担を減らす

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク： Ruby on Rails 8.1.x
  - RUNTEQで学んだ技術を活かせる
  - 認証、データベース操作で情報管理が行いやすい
  - メール通知機能が標準機能で備わっているため
- フロントエンド：HTML TailwindCSS 4.2.x
  - シンプルなUIを作成するため
- DB： PostgreSQL 18.2
  - Ruby on Railsとの相性が良いため
- デプロイ先： Render 
  - 無料枠にて実施でき、デプロイが簡単なため
- 使用予定ライブラリ
  - (ユーザー登録)
      - gem devise：新規登録、ログイン機能、ログアウト
      - gem devise-i18n：devise機能日本語化
  - (UI関連)
    - gem i18n：日本語設定のため
  - (テスト駆動)
    - gem rspec-rails：Rspecテスト導入のため
    - gem factory-bot：RSpecテスト実行のため
    - gem selenium-webdriver：RSpecテスト実行のため
    - gem faker：factory-botでアカウントテスト作成のため
    - gem letter_opener_web：パスワードリセット確認のため(本リリース時に実装予定)

### テーブル詳細
#### ：users
- name : string / 氏名(ユーザー)
- email : string / ログイン用メールアドレス(ユニーク制約)
- tel_number : string / ログイン用電話番号(ユニーク制約) 本リリース実装予定
- encrypted_password : string / ログイン用パスワード
- created_at : timestamp / 作成日
- updated_at : timestamp / 更新日

#### ：care_users
- family_id : integer
- name : string / 氏名(要介護者)
- birthday : date / 生年月日
- blood_type : string / 血液型(列挙型で選択)
- medical_condition_1 : string / 病名-1(文字数制限 : 50)
- medical_condition_2 : string / 病名-2(文字数制限 : 50)
- medical_condition_3 : string / 病名-3(文字数制限 : 50)
- invite_code : string / 招待コード
- created_at : timestamp / 作成日
- updated_at : timestamp / 更新日

#### ：family_members(中間テーブル)
- user_id : integer / FK1
- family_id : integer / FK2
- role : integer / main(主介護者) family(家族)判別
- created_at : timestamp / 作成日
- updated_at : timestamp / 更新日

#### : families
- family_name : 家族名
- created_at : timestamp / 作成日
- updated_at : timestamp / 更新日

#### ：care_records
- user_id : integer / FK1
- care_user_id : integer / FK2
- health_status : integer / 体調(良い・変わらない・悪い)
- appetite : integer / 食欲(ある・変わらない・ない)
- sleep_quality : integer / 睡眠(多い、変わらない、少ない)
- memo : string / 特記事項(文字数制限 : 255)
- created_at : timestamp / 作成日
- updated_at : timestamp / 更新日
